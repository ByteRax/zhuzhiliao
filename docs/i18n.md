# i18n 改造文档

本文件记录竹知了国际化改造的方案、约定与后续计划。改造遵循项目"零依赖、无构建"铁律。

## 1. 方案摘要

### 技术栈（探测结论）

| 项 | 真实情况 |
|----|----------|
| 形态 | 单文件零依赖原生应用（`index.html` 1820 行） |
| 构建 | **无**（无 package.json、无 Vite/Webpack/Rollup） |
| 语言 | 原生 ES Modules + 动态 import，无 TypeScript |
| 框架/路由/状态 | 无 |
| SSR | 无（纯 CSR） |
| i18n 残留 | 无 |

### 选型

- **采纳：自研零依赖 i18n 模块**（`i18n/i18n.js`，约 380 行原生 ESM）。
- **被否决**：i18next（需引入运行时 + fetch 包装，违背零依赖精神）；@formatjs/intl（ICU MessageFormat 杀鸡用牛刀，本项目无复杂插值/复数/CJK 富文本需求）；vue-i18n/react-i18next（项目非 Vue/React）。
- 版本说明：本项目无 npm 依赖，故无"包版本号"；自研模块版本随仓库提交。

### 语言检测流程（伪代码）

```
function detectLocale(env):
    if 传入 env 桩:          # 测试隔离
        只读 env，不回退真实 navigator
    # 1. URL ?lang= （白名单校验，非法值忽略）
    hit = normalize(searchParams['lang'])
    if hit: return { locale: hit, source: 'url' }
    # 2. localStorage['app_locale']
    raw = safeLsGet('app_locale')   # try/catch SecurityError
    hit = normalize(raw)
    if hit: return { locale: hit, source: 'localStorage' }
    # 3. navigator.languages 逐项归一化
    for tag in navigator.languages:
        hit = normalize(tag)
        if hit: return { locale: hit, source: 'navigator.languages' }
    # 4. navigator.language
    hit = normalize(navigator.language)
    if hit: return { locale: hit, source: 'navigator.language' }
    # 5. fallback
    return { locale: 'zh-cn', source: 'fallback' }
```

### 归一化规则

- 转小写；
- `en-US`/`en-GB`→`en`；`ja-JP`→`ja`；`ko-KR`→`ko`；
- 中文系（`zh-TW`/`zh-HK`/`zh-Hant`/`zh-SG`/`zh` 无 region）一律→`zh-cn`（本项目只提供简体译文）；
- 未知语言→`null`（最终落 `zh-cn` fallback，不写入 localStorage）。

## 3. key 命名约定

- 点分层级：`{命名空间}.{区块}.{条目}`，如 `ui.btn.auto`、`faq.faq.q1`。
- 命名空间与目录文件对应：`ui`→`ui.json`、`faq`→`faq.json`、`error`→`error.json`。
- 区块按语义分组，不按页面位置：`brand`/`hint`/`meter`/`btn`/`stats`/`lore`/`installTip` 等。
- 条目用语义名（`auto`/`autoOff`），不用位置名（`btn1`）。
- 富文本用占位符 `{brand}` `{cyber}`，由 `data-i18n-rich` + `data-i18n-rich-strong` 声明式渲染（DOM 构建，非 innerHTML）。
- 插值用 `{name}` 命名占位符，由 `interpolate()` 或 `t(key, params)` 处理。
- 品牌/专有名词不译：`Zhuzhiliao` 在 en/ja/ko 保持原文。
- 四语 key 集合由 `scripts/check-locales.mjs` 保证严格一致。

### 已运行测试结果（真实）

- `check-locales.mjs`：✅ 通过。四语各 71 个 key 完全一致，无空译文。
- `test-i18n.mjs`：✅ 24/24 通过（normalizeLocale 8 + detectLocale 12 + interpolate 4）。覆盖 ja-JP/ko-KR/en-GB/zh-TW/fr-FR/空/undefined/非法值 等 ≥8 用例。
- `test-i18n-integration.mjs`：✅ 5/5 通过（含 t/lang/localStorage 三者同步、路径遍历拒绝、切换竞态）。
- 浏览器验证：✅ en（navigator 检测）/ ja（?lang=ja）/ ko（?lang=ko）/ zh-cn（fallback）四语渲染正确；ENABLE_I18N=false 时回归中文。

## 5. 安全自检（对照任务安全要求）

1. **禁止 v-html/innerHTML**：✅ 译文统一走 `textContent`；富文本（FAQ `<strong>`、安装引导多行）用 `createElement` + `textContent` 逐节点构建，`data-i18n-rich` 插槽方案。原 `tip.innerHTML = ...` 已移除。
2. **白名单校验防路径遍历**：✅ `normalizeLocale()` 白名单过滤 + `resourceUrl()` 二次校验 `SUPPORTED.includes(lang)`；集成测试验证 `setLocale('../etc/passwd')` 被拒。
3. **localStorage 异常捕获**：✅ `safeLsGet/safeLsSet` 全 try/catch，隐私模式 SecurityError 静默。
4. **资源文件无敏感信息**：✅ 四语 JSON 仅含 UI 文案，无密钥/接口地址/账号。
5. **第三方翻译 API**：N/A，本项目未接入机器翻译，译文全部人工/人工校对。

## 6. 边界情况覆盖

| 边界 | 处理 |
|------|------|
| `navigator.languages` 空/undefined | detectLocale 跳过该步继续后续检测，单测覆盖 |
| SSR 中 window 未定义 | detectLocale 顶部 `typeof window === 'undefined'` 判断，直接 fallback |
| localStorage SecurityError | safeLsGet/Set try/catch，单测桩覆盖 |
| 存储的语言代码已下线 | normalizeLocale 返回 null，检测忽略继续；不写入新值 |
| 语言包 404/JSON 解析失败 | loadBundle 抛错 → setLocale 回滚 → reportError；init 兜底 fallback |
| 同一 key 部分语言缺失 | t() 回退到 fallback 语言值；check-locales.mjs CI 保证不发生 |
| 译文空字符串 | 按契约允许，t() 原样返回 |
| 切换竞态（后发起先返回） | switchSeq 序列号保护，过期结果丢弃，集成测试验证 |
| 超长译文布局溢出 | CSS 已用 `white-space`/`max-width`；ja/ko 译文长度与中文相近，未观察到溢出（浏览器截图确认） |

## 7. 回滚方案

### 灰度开关

- `window.ENABLE_I18N = false`（在引入 i18n.js 前设置）：关闭后 init 只加载 zh-cn fallback，页面行为与改造前一致。已浏览器验证。
- 关闭后 SEO meta（始终中文）与 UI 文案（兜底中文）均与改造前一致。

### 回滚步骤

1. 关闭开关：在 `<head>` 顶部加 `<script>window.ENABLE_I18N=false;</script>`（或直接 revert 提交）。
2. revert 对应提交（按阶段拆分，见下）。
3. 验证清单：
   - 页面显示中文；
   - 物理模拟、声音、计数正常；
   - 无 console 报错。

### 按阶段提交（便于单点 revert）

1. **基础设施**：`i18n/i18n.js`
2. **资源**：`locales/**`、`scripts/check-locales.mjs`
3. **迁移**：`index.html`、`docs/i18n.md`
4. **测试**：`scripts/test-i18n*.mjs`、`scripts/scan-cjk.mjs`

## 8. 已知限制与后续建议

1. **首屏 FOUC**：纯 CSR，HTML 原始语言 → JS 执行后切语言，有短暂闪烁。子路径版本（`/en/` 等）的 HTML 原始语言已是目标语言，FOUC 主要发生在根路径 `/`（中文 HTML + navigator 检测切其他语言时）。
2. **SEO 国际化已实现**：见下方 §9「SEO/GEO 国际化」。title/description/OG/JSON-LD/hreflang/sitemap/llms/manifest/404 均已四语化。
3. **noscript 区**：无 JS 环境显示当前 HTML 版本的语言原文（子路径 `/en/` 的 noscript 是英文，因为生成时由 seo.json 注入；但 noscript 内 data-i18n 标记在无 JS 时不替换，显示 HTML 源码值）。
4. **资源加载用 fetch**：`file://` 直开时 fetch 受 CORS 限制可能失败 → i18n 静默回落中文（兜底）。子路径版本用 `<base href="/">` 确保相对资源解析到根。
5. **无复数/ICU**：自研模块不含 plural 规则；本项目 CJK 无复数、英文场景极少，暂不需要。
6. **浏览器模块缓存**：开发时改 `i18n/i18n.js` 后需硬刷新（Cmd+Shift+R），否则 `import()` 返回缓存的旧模块。部署后首次访问无此问题。

## 9. SEO/GEO 国际化（子路径方案）

### 架构

```
src/index.html (模板，含 {{seo.xxx}} 占位符)
  + locales/{zh-cn,en,ja,ko}/seo.json (四语 SEO 资源 + JSON-LD)
  → scripts/build-seo.mjs 生成 →
    /index.html        (中文根路径，canonical=/)
    /en/index.html     (canonical=/en/)
    /ja/index.html     (canonical=/ja/)
    /ko/index.html     (canonical=/ko/)
```

### URL 方案

- 中文留根路径 `/`（零收录冲击，现有外链/分享/收录不变）
- 英文 `/en/`、日文 `/ja/`、韩文 `/ko/`
- `x-default` 指向根路径中文

### hreflang 互链

每份 HTML 含全部四语 + x-default 互指：
```html
<link rel="alternate" hreflang="zh-Hans" href="https://zzl.tanranran.cn/">
<link rel="alternate" hreflang="en" href="https://zzl.tanranran.cn/en/">
<link rel="alternate" hreflang="ja" href="https://zzl.tanranran.cn/ja/">
<link rel="alternate" hreflang="ko" href="https://zzl.tanranran.cn/ko/">
<link rel="alternate" hreflang="x-default" href="https://zzl.tanranran.cn/">
```

### JSON-LD

每语言一份完整 JSON-LD（WebSite/WebPage/WebApplication/HowTo/FAQPage/Person），`@id`/`url` 按语言路径区分（如 `https://zzl.tanranran.cn/en/#website`），`inLanguage` 对应（`en`/`ja`/`ko`/`zh-CN`）。

### 生成与维护

```bash
# 生成四语 HTML（改了 src/index.html 或 seo.json 后运行）
node scripts/build-seo.mjs

# SEO 一致性检查（CI 用）
node scripts/check-seo.mjs
```

日常维护：
- 改 UI 代码（物理/声音/<body>）→ 改 `src/index.html` → `node scripts/build-seo.mjs`
- 改 SEO 文案 → 改 `locales/{lang}/seo.json` → `node scripts/build-seo.mjs`
- 生成的 4 份 HTML 提交进仓库，部署时不需跑脚本（Cloudflare Pages 直接托管）

### 多语言静态资产

- `sitemap.xml`：四语 URL + hreflang 互指 + 各语 image:title/caption
- `sitemap.txt`：四语路径
- `llms.txt`（中文根）+ `llms.en.txt`/`llms.ja.txt`/`llms.ko.txt`
- `manifest.webmanifest`（中文根）+ `en/manifest.webmanifest` 等（start_url/scope 指各自语言根）
- `404.html`（中文根）+ `en/404.html` 等
- `robots.txt`：无需改（全站允许，Sitemap 指向根 sitemap.xml）

### 路径协调（i18n 运行时）

`detectLocale` 新增 pathname 检测（优先级：`?lang=` → pathname 前缀 → localStorage → navigator → fallback）。
访问 `/en/` 时，pathname 检测返回 `en`，确保运行时 UI 语言与静态 HTML 语言一致，避免 localStorage 记忆导致串语言。

### 子路径资源解析

子路径 HTML 用 `<base href="https://zzl.tanranran.cn/">`，让 `./i18n/i18n.js`、`./3d/boot3d.js`、`locales/...` 等相对引用解析到站点根（避免 `/en/i18n/i18n.js` 404）。
